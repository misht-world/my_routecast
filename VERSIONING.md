# Порядок версий и документирования

Текущая подготовленная версия: **0.4.1**. Последний существующий релизный тег: **v0.4**.

1. Для каждого набора исправлений добавлять запись в CHANGELOG.md с датой,
   поведением до/после, результатами проверок и известными ограничениями.
2. Исправления увеличивают patch (0.4 → 0.4.1), новые возможности — minor,
   несовместимые изменения приложения — major. Android versionCode всегда увеличивать.
3. Согласованно менять android/app/build.gradle.kts, watch/source/Cfg.mc и README.md.
   Номер протокола независим; менять его только при изменении схемы обеих сторон.
4. Сохранять изменения отдельными Git-коммитами. Не переписывать прежние версии
   и не переносить существующие теги. Пользовательские файлы вне изменений не включать.
5. До выпуска пройти Gate 1–3 из testing.md; Gate 4 подтвердить на устройствах
   для Bluetooth, GPS, энергопотребления и лимитов памяти. Записать фактические результаты.
6. Только после этих проверок создавать неизменяемый тег vX.Y.Z и артефакты
   routecast-android-hw-X.Y.Z.apk / routecast-watch-instinct3-X.Y.Z.prg.
   Хранить SHA-256 файлов вместе с записью о релизе и идентификатором коммита.

0.4.1 пока не помечать релизным тегом: сквозные и аппаратные проверки не завершены.
